# Card Prep Script Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A command-line tool that turns a folder of MP3s into a prepared microSD card: FAT32-checked, short ASCII filenames, art and oversized tags stripped, leading silence trimmed, loudness normalised, and a fixed-width `index.txt` the firmware can seek into.

**Architecture:** A small Python package, `cardprep`, that shells out to `ffmpeg` for all audio work and does file naming, index writing, and card checks itself. Pure functions for naming and index encoding are unit tested without ffmpeg; the ffmpeg path is tested against short synthetic tone files generated by ffmpeg in a fixture.

**Tech Stack:** Python 3.12, `ffmpeg` and `ffprobe` on PATH, `pytest`. No other runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-25-random-song-button-design.md`, section "Card preparation".

## Global Constraints

- Never modify or delete a file in the source folder. Only write to the card path.
- Card must be FAT32. Refuse to run (exit code 2) if the card filesystem is not FAT32 or the card is larger than 32 GB.
- Output filenames: ASCII only, at most 40 characters including `.mp3`, pattern `NNNN-slug.mp3` where `NNNN` is zero-padded 1-based.
- Index file name on the card: `index.txt`. Song folder on the card: `songs/`.
- Index format (shared with firmware, exact):
  - Header: the text `SONGBUTTON 1 <count>` where count is decimal with no padding, followed by spaces to make the header exactly 31 bytes, then `\n` (32 bytes total).
  - Records: one per song, each exactly 128 bytes: `<filename>\t<title>` encoded UTF-8, padded with spaces to 127 bytes, then `\n`. Title is truncated so the record fits. Filename is ASCII; title may be UTF-8 but is cut on a character boundary.
  - Record N (0-based) starts at byte offset `32 + 128 * N`.
- Loudness target: integrated loudness -16 LUFS, true peak -1.5 dBTP (ffmpeg `loudnorm=I=-16:TP=-1.5:LRA=11`).
- Leading silence trim: remove silence below -50 dB at the start of the file (ffmpeg `silenceremove=start_periods=1:start_threshold=-50dB`).
- Strip all metadata and attached pictures: ffmpeg `-map_metadata -1 -vn`.
- Output MP3 at 192 kbps CBR (`-c:a libmp3lame -b:a 192k`), 44.1 kHz, stereo preserved (the firmware sums to mono).

## Review Focus

1. Two source files whose slugs collide (for example `Song.mp3` and `song.MP3`) must both land on the card under different names; tested in Task 2.
2. A source file ffmpeg cannot decode (corrupt or not actually MP3) must be skipped with a warning and the run must still finish; tested in Task 4.
3. A source folder with more than 9999 files must fail fast with a clear message rather than produce a malformed index; tested in Task 2.
4. A title containing multi-byte UTF-8 near the 127-byte cut must not be split mid-character, producing invalid UTF-8 the firmware would print garbage for; tested in Task 3.
5. Re-running the script on a card that already has `songs/` and `index.txt` must replace them atomically enough that an aborted run does not leave an index that references missing files: write to `index.tmp` and rename last; tested in Task 5.

**Interfaces:**

- Produces: `check_card(path: Path) -> None` raising `CardError` unless the filesystem is FAT32 (macOS: `diskutil info` "File System Personality: MS-DOS FAT32"; Linux: `findmnt -no FSTYPE` is `vfat`) and the volume is 32 GB or smaller; `main(argv: list[str] | None = None) -> int` with usage `cardprep SOURCE_DIR CARD_DIR [--skip-card-check]`.
